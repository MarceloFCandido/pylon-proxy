## Directory Purposes

**backend/cmd/pylon-proxy:**
- Purpose: Backend service entry point
- Contains: Single main.go file with server initialization
- Key files: `main.go` - initializes Echo, registers routes, sets up graceful shutdown

**backend/internal/api:**
- Purpose: HTTP request handling and routing
- Contains: Handler functions and route registration
- Key files: `handlers.go` (GetUsers, GetTeams, GetIssuesWaitingOnUser, health check, OpenAPI), `routes.go` (route mapping)

**backend/internal/client:**
- Purpose: External API integration
- Contains: Pylon API client implementation
- Key files: `pylon.go` - HTTP request execution, account fetching with VIP detection

**backend/internal/config:**
- Purpose: Configuration management
- Contains: Constants and environment-based settings
- Key files: `config.go` - static Pylon API URL, port configuration

**backend/internal/models:**
- Purpose: Type definitions for serialization/deserialization
- Contains: Go struct definitions with JSON tags
- Key files: `models.go` - User, Team, Issue, Account, SimplifiedUser, SimplifiedTeam, SimplifiedIssue

**backend/internal/service:**
- Purpose: Business logic and data transformation
- Contains: Service functions for complex operations
- Key files: `issue.go` - GetIssuesWaitingOnUser (filtering, VIP detection, sorting)

**backend/pkg/utils:**
- Purpose: Reusable utility functions
- Contains: Sorting and data manipulation
- Key files: `sort.go` - SortIssues, SortUsers, SortTeams

**frontend/cmd/pylon-proxy:**
- Purpose: Frontend service entry point
- Contains: Single main.go file with server initialization
- Key files: `main.go` - initializes Echo, registers routes, sets up graceful shutdown

**frontend/internal/api:**
- Purpose: HTTP routing and request forwarding
- Contains: Handler functions, proxy configuration
- Key files: `handlers.go` (health check, proxy setup), `routes.go` (static serving, proxy routing)

**frontend/internal/config:**
- Purpose: Configuration management
- Contains: Environment-based settings for proxy URL and port
- Key files: `config.go` - environment variable loading with defaults

**frontend/assets/src/js:**
- Purpose: Frontend application logic
- Contains: Core modules for routing, API communication, state management
- Key files: `main.ts` (App initialization), `api.ts` (ApiClient), `router.ts` (client-side routing), `storage.ts` (localStorage wrapper)

**frontend/assets/src/js/pages:**
- Purpose: Page-level components
- Contains: Individual page implementations
- Key files: `home.ts` (API key input), `issues.ts` (issues list display)

**frontend/assets/src/types:**
- Purpose: TypeScript type definitions
- Contains: Interface definitions for API responses and application types
- Key files: `api.ts` (User, Team, Issue), `app.ts` (Theme, RouteHandler), `global.d.ts` (window augmentations)

**frontend/assets/src/styles:**
- Purpose: Application styling
- Contains: CSS files for layout, theming, components
- Key files: `main.css` (global styles), `themes.css` (light/dark theme variables), `components.css` (component styles)

**frontend/dist:**
- Purpose: Built frontend artifacts (generated)
- Contains: Webpack-bundled JavaScript and CSS
- Key files: `index.html`, `assets.*.js`, `assets.*.css` - compiled and minified code

## Key File Locations

**Entry Points:**
- `backend/cmd/pylon-proxy/main.go`: Backend service starts here, initializes Echo and registers routes
- `frontend/cmd/pylon-proxy/main.go`: Frontend service starts here, initializes Echo and registers routes/proxy
- `frontend/assets/src/js/main.ts`: Frontend JavaScript runs here after DOMContentLoaded event

**Configuration:**

**Core Logic:**

- `backend/internal/client/pylon.go`: API integration with Pylon service
- `frontend/assets/src/js/api.ts`: Frontend-to-backend communication
- `frontend/assets/src/js/router.ts`: Client-side routing and page rendering

**Testing:**
- No dedicated test files found in codebase (testing not implemented)

## Naming Conventions

**Files:**
- Go source files: lowercase with underscores for compound names (e.g., `pylon.go`, `issue.go`)
- TypeScript files: lowercase with dots for path hierarchy (e.g., `api.ts`, `pages/home.ts`)
- Configuration files: lowercase with descriptive names (e.g., `tsconfig.json`, `webpack.config.js`)
- Build artifacts: use hash-based names generated by Webpack (e.g., `assets.789931e5.js`)

**Directories:**
- Go packages: lowercase single words (api, client, config, models, service, utils)
- Frontend source structure: lowercase organizing by type (js/, types/, styles/)
- Entry points: `cmd/[appname]` follows Go convention
- Internal code: `internal/` package marks code not for external use

**Functions/Classes:**
- Go functions: PascalCase for exported, camelCase for unexported (GetUsers, doRequest)
- TypeScript classes: PascalCase (ApiClient, Router, Storage, App)
- TypeScript methods: camelCase (getApiKey, testApiKey, navigate)
- Type definitions: PascalCase (User, Team, Issue)

**Variables:**
- Go: camelCase for local variables, PascalCase for struct fields with JSON tags
- TypeScript: camelCase for variables and properties (apiKey, baseUrl)

## Where to Add New Code

**New Backend API Endpoint:**
1. Create handler function in `backend/internal/api/handlers.go`
2. Register route in `backend/internal/api/routes.go`
3. Add data models in `backend/internal/models/models.go` if needed
4. If complex logic needed, add service function in `backend/internal/service/`
5. Use existing `client.DoRequest()` for API calls to Pylon

**New Frontend Page:**
1. Create page component in `frontend/assets/src/js/pages/[pagename].ts`
2. Register route in `frontend/assets/src/js/main.ts` (in setupRoutes method)
3. Add TypeScript types in `frontend/assets/src/types/` if needed
4. Add page-specific CSS in `frontend/assets/src/styles/components.css`

**New Utility Function:**
- Backend: `backend/pkg/utils/[function].go`
- Frontend: Create new file in `frontend/assets/src/js/utils/` (currently doesn't exist, create as needed)

**New API Type:**
- Backend responses: Add struct in `backend/internal/models/models.go`
- Frontend types: Add interface in `frontend/assets/src/types/api.ts`
